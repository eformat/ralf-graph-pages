Module 02: Evaluate results and run the RAG pattern

In this module you will work through the core AutoRAG workflow end to end in French: create the optimization run in the two-step wizard, monitor the run, review the leaderboard, choose the best RAG pattern, and run it in a workbench with the generated notebooks. Nothing in the wizard asks you for a language — AutoRAG detects the language of your evaluation questions automatically; the multilingual work happens in the models and data you feed it (staged in Module 01).

Learning objectives:

  • Create a multilingual AutoRAG optimization run — French corpus, French evaluation data set, multilingual models — and understand how the wizard handles language without a language selector

  • Interpret leaderboard scores for the AutoRAG evaluation metrics on non-English answers

  • Compare RAG patterns using pattern details and French Sample Q&A results

  • Run the selected pattern in a workbench with the indexing and inference notebooks

This feature is Generally Available in Red Hat OpenShift AI 3.6. The multi-language support that graduated to GA in 3.6 works without a language input in the wizard: AutoRAG auto-detects the language of the evaluation questions, and the multilingual models plus the target-language data you staged in Module 01 carry the French run.

Exercise 1: Create the French optimization run

Optimization runs cannot be edited after creation. Choose your connection, metric, preset, and models carefully before you click Create run.

  1. In the RHOAI dashboard, click Gen AI studio > AutoRAG.

  2. Select the autorag-ml-demo project, and then click Create AutoRAG optimization run.

  3. In step 1, enter a name and optionally a description for the run, select the MaaS connection, and click Next. The step-1 field is MaaS connection — it lists the project’s MaaS connections: Secrets with the opendatahub.io/connection-type: maas annotation and MAAS_BASE_URL / MAAS_API_KEY data keys (exactly the shape staged in Module 01, pointing at the facade route). Select aml-maas-models. If the typeahead renders "There are no secrets in the selected namespace", use Add new connection instead — two Base URL rules from the live wizard:

    • The dialog accepts only HTTPS URLs (or localhost HTTP) — in-cluster plain-HTTP service URLs are rejected, so the endpoint needs an edge-TLS route.

    • The Base URL must not end in /v1. The dashboard backend appends /v1 itself: a /v1-suffixed value makes it call <host>/v1/v1/models, which returns 404 and the wizard shows "Failed to load MaaS models".

Name:          aml-fr-autorag-01
Description:   French (multilingual) AutoRAG optimization run — fed-aura-fr regulatory corpus, bge-m3 + llama-3.2-3b via OGX
Connection:    aml-maas-models

  1. In step 2, configure the knowledge setup:

    1. Select the aml-s3-connection S3 connection and browse the bucket for the fed-aura-fr folder — the wizard shows a single folder containing banque-aura-politique-reglementaire.md, the French regulatory compendium.

    2. Select pgvector (remote) from the Vector I/O provider list — the provider OGX exposes under its vector_io APIs.

    3. Add the evaluation data set by browsing the bucket for eval-dataset-fr.json — ten French question/answer pairs in [{"question", "correct_answers", "correct_answer_document_keys"}] format, all referencing banque-aura-politique-reglementaire.md as the source document.

    4. Select an optimization metric from the Optimization metric list. With the Faster preset the wizard offers exactly three metrics (captured from the live 3.6 dropdown):

      Metric What it measures Choose it when

      Faithfulness (Unitxt)

      Whether the generated answer uses information from the retrieved context rather than hallucinated content — a high score means the answer uses the retrieved documents, not the model’s training data

      Groundedness and traceability to source documents are critical, such as in compliance or legal use cases — the case for this regulatory corpus

      Answer correctness (Unitxt)

      Whether the generated answer matches the expected answers in your evaluation data set

      You have well-defined expected answers and want the system to match them closely

      Overall score

      A composite score that combines the other metrics to provide an overall assessment of the RAG system’s performance

      You want a single ranking number across all evaluated aspects

      Select Faithfulness (Unitxt) — the default for the Faster preset and the right pick for a regulatory corpus.

      There is no language selector in the 3.6 AutoRAG wizard — not on step 1, not in step 2, not in the models dialog, not when you switch presets (verified against the live wizard and its JavaScript bundles: no language, locale, or language-option strings exist in any wizard screen). Do not look for one. Multilingual support needs no language input because AutoRAG auto-detects the language of the evaluation questions: with the French questions in eval-dataset-fr.json, the LLM-as-judge metrics grade the generated French answers against the French ground truth in the corpus’s language. What actually makes the run multilingual is what you supply: the multilingual embedding model (bge-m3), the non-English corpus, and the evaluation data set written in the target language.

      The run preset also decides which metrics score each pattern. The Faster preset scores every RAG pattern on Faithfulness (Unitxt), Answer correctness (Unitxt), and Overall score. Switching the preset to Better quality adds four RAGAS metrics to that list: Faithfulness (RAGAS), Answer relevancy, Context precision, and Context recall — richer signal, at double the resource footprint (8 vCPU / 32 GiB vs 4 vCPU / 16 GiB).

    5. In the Maximum RAG patterns field, keep the default value 8 (valid range 4-20).

    6. Select the Faster run preset — recursive chunking on exported text with chunk sizes 128, 256, or 512 tokens, requiring 4 vCPU and 16 GiB. The Better quality preset (hybrid chunking, Docling table parsing, 8 vCPU / 32 GiB) is the richer alternative; on this CPU-only cluster Faster keeps the run tractable.

    7. Optional: click Edit on the model configuration card to review the discovered models. AutoRAG discovers models through the step-1 MaaS connection — the facade’s /v1/models lists the tool-calling foundation model (aml-llama32-3b) and the multilingual embedding model (aml-bge-m3, 1024-dim) — and both stay selected. Point the connection at an endpoint that does not list both model types and the models dialog stays empty.

  2. Click Create run. AutoRAG begins testing RAG configurations against the French corpus; you can monitor the status on the AutoRAG page.

For embedding models, BAAI/bge-m3 is the recommended choice whenever your documents are not English: it supports more than 100 languages, dense and sparse retrieval, and requires approximately 1.1 GB of memory (fp16). The auto-detected question language configures the judge; the embedding model configures the retrieval — a French run needs both.

Verify

On the AutoRAG page, the aml-fr-autorag-01 run is listed with a status of Running or Pending, with the underlying documents-rag-optimization-pipeline pipeline run progressing. The run reaches Complete when AutoRAG finishes testing all RAG configurations.

On the cluster, the run materializes as pipeline pods in autorag-ml-demo:

oc get pods -n autorag-ml-demo --sort-by=.status.startTime | tail -5

Keep in mind while your run executes:

  • A maximum of three foundation models and two embedding models per optimization run. Specifying more models can cause the run to fail.

  • CPU-only model servers make a run slower than a GPU-backed cluster — the Faster preset on one tool-calling foundation model is the deliberate budget of this workshop.

  • Images embedded in documents are not processed, and OCR is not available for PDF documents; the French corpus is Markdown, so it indexes cleanly.

Exercise 2: Evaluate the French leaderboard

With the Faster preset selected in Exercise 1, every AutoRAG optimization run scores each RAG pattern on three metrics, scored from 0 to 1 with higher being better. Each score includes a mean value, a high confidence interval (CI high), and a low confidence interval (CI low):

  • Faithfulness (Unitxt) — measures whether the generated French answer uses information from the retrieved context rather than hallucinated content. The judge grades in the language it auto-detected from the evaluation questions — French, for this workshop’s data set.

  • Answer correctness (Unitxt) — measures whether the generated answer matches the French expected answers in eval-dataset-fr.json.

  • Overall score — a composite score that combines the other metrics to provide an overall assessment of the RAG system’s performance.

(A Better quality preset run adds Faithfulness (RAGAS), Answer relevancy, Context precision, and Context recall columns to the same leaderboard.)

Read metric scores together:

  • High faithfulness with low answer correctness means the answer is grounded in the retrieved context, but the context does not contain the most accurate answer — check whether the chunking strategy splits the French policy tables that carry the thresholds.

  • High answer correctness with low faithfulness means the model draws on training data rather than retrieved documents.

  • Low scores across the board with fluent-looking answers usually points at retrieval — open the pattern details and compare the winning chunking and embedding configuration against the other patterns before blaming the generation model.

  1. In the RHOAI dashboard, click Gen AI studio > AutoRAG, select the autorag-ml-demo project, and click aml-fr-autorag-01.

  2. Review the leaderboard, which ranks RAG patterns by your selected optimization metric. Compare scores across all metric columns; an indicator marks the optimization metric.

  3. To view detailed information about a pattern, click the pattern name or select View details from the actions menu. The pattern details view shows:

    1. Scores for each metric with mean, CI high, and CI low values

    2. Configuration settings organized by category: chunking, embedding, retrieval, and generation — note which embedding configuration won and its dimensionality

    3. Sample Q&A results with per-question scores, your French expected answers, and the pattern’s generated French answers

  4. Compare patterns by examining Sample Q&A responses across patterns — with a regulatory corpus, read the generated French answers against the policy wording: a correct RTO/RPO or CET1 threshold answer that misquotes the policy is a faithfulness problem, not a retrieval problem.

  1. Optional: To test a pattern interactively, select Try this pattern from the actions menu. A chat panel opens where you can ask questions about the French policies — for example « Dans quels délais un incident majeur lié aux TIC doit-il être signalé à l’autorité compétente selon DORA ? » — and switch between patterns to compare responses.

  2. After you choose a pattern, get code snippets for integrating it into your application by using the Responses API: click View code from the actions menu on the leaderboard. Snippets are available in curl, Node.js, Go, and Python. By default, snippets fetch OGX credentials from the Kubernetes secret at runtime.

  3. To explore the pattern interactively in a workbench instead, select Save as indexing notebook and Save as inference notebook from the actions menu.

Enable Inject credentials only for quick tests: it embeds your OGX hostname and API key directly in the snippet. Treat injected snippets as secrets.

Verify

You have selected a RAG pattern based on its leaderboard scores and French Sample Q&A results, and you have either copied a Responses API code snippet or downloaded the indexing and inference notebooks for the selected pattern.

With a winning pattern in hand, the next exercise runs it against your French documents in a workbench.

Exercise 3: Run the RAG pattern in a workbench

  1. In the RHOAI dashboard, open your workbench in the autorag-ml-demo project.

  2. Attach the following data connections to the workbench. Use the same S3 bucket and OGX instance that you used for the optimization run:

    1. An S3-compatible object storage connection for your documents — aml-s3-connection

    2. A connection for your OGX instance that includes the API key and base URL — aml-ogx-connection

  3. Optional: To index additional French documents, upload and run the indexing notebook. The vector database is already populated from the optimization run.

  4. Upload the inference notebook to the workbench.

  5. Open the inference notebook and run each cell. The notebook prompts you to enter a question — enter a question in French about your documents, for example:

Quel est notre risque de concentration vis-à-vis d'AWS et quelles mesures d'atténuation sont requises ?
The chat panel from Try this pattern is for testing purposes only. Your chat history is lost if you switch patterns or close the panel; the inference notebook is the durable way to exercise the pattern.

Verify

The inference notebook returns answers grounded in your French documents — the concentration-risk answer quotes the policy’s 33 % AWS expenditure threshold and its mitigation requirements. If you ran the indexing notebook, all its cells completed without errors.

If the notebook displays an error, check your connection details — most failures at this step are a mismatched S3 bucket or OGX connection rather than a pattern problem.

You have now completed the full multilingual AutoRAG workflow from French test data to a running RAG pattern.

Module summary

What you accomplished:

  • Created a French AutoRAG optimization run — no language input anywhere in the wizard; the question language was auto-detected

  • Evaluated the leaderboard and pattern details across the evaluation metrics on French answers

  • Compared patterns using French Sample Q&A results and captured a Responses API snippet or notebooks

  • Ran the selected pattern in a workbench and verified grounded French answers

Key takeaways:

  • Auto-detection configures the judge, the embedding model configures the retrieval, and the evaluation data set anchors both to the target language — a non-English run needs multilingual models and target-language data, not a language setting

  • Mean scores alone can mislead: read faithfulness, correctness, and context correctness together to spot retrieval or generation problems, and read French Sample Q&A against the policy wording

  • The pattern details view exposes the winning chunking, embedding, retrieval, and generation settings — reuse them as defaults for future runs on the same corpus
